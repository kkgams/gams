01 / PROJECTSSTART WITH YOUR DIRECTORY

YOUR WORK HAS A HOME

A Project.
Not a preset.

A GAMS Project is an external directory rooted at gams.json. It owns its configuration, content, and choice of Project Units. The Host opens it; it does not bundle a Project of its own.

03 / THE RUNTIMETHE HOST DOES ITS PART

SHARED FOUNDATIONS

Less shell.
More Project.

The Host provides the runtime and shared browser UI APIs. Project Units supply the tools and behavior, without becoming part of the Host itself.

01

WASM plugins.

Run component-based plugins through the runtime. Keep tool capabilities in independently maintained Units.

02

Browser-rendered Views.

Build Views with Host-owned widgets, helpers, and semantic UI contracts. Let the Project's theme shape their presentation.

03

Visible startup.

Follow Unit downloads, ZIP extraction, cache reuse, and initialization through the Host's startup progress screen.

04 / OWNERSHIPCLEAR BOUNDARIES

YOUR PROJECT STAYS YOURS

Keep the Host.
Change the parts.

Project configuration lives in your directory. Views and plugins own their persistent state; the Host coordinates save hooks and writes the current configuration back to gams.json.

HOST Runtime, shell, shared UI APIs

PROJECT Configuration, content, selected Units

PROJECT UNITS Tools, behavior, persistent state
